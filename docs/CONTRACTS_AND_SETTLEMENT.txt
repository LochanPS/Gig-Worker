--------------------------------------------------------------------------------
1. THE BIG PICTURE — WHERE CHAIN MEETS BACKEND
--------------------------------------------------------------------------------
The backend payment orchestrator (backend/src/modules/payments/payment.service.ts)
drives every payment through its state machine. At two points it needs the chain:

  RATE_LOCKED --(fund escrow)--> FUNDED --(release)--> SETTLING --> COMPLETED
                     |                         |
                     v                         v
              Settlement.fund()         Settlement.release()

It also anchors each compliance decision hash on-chain at create time
(AuditAnchor). The orchestrator NEVER imports viem or contract ABIs directly —
it talks to a single port interface (see §3). Today a SIMULATED implementation
of that port ships in the backend so the whole lifecycle works with no chain.
P1's job: implement the SAME interface for real and register it at boot.

--------------------------------------------------------------------------------
2. THE FOUR CONTRACTS (P1 OWNS — Solidity 0.8.x, Foundry)
--------------------------------------------------------------------------------
Signatures are FROZEN in docs/BUILD_CONTRACTS.txt §6. Summary:

  MockUSDC.sol        ERC-20, 6 decimals, onlyOwner mint(address,uint256).
                      Faucet-minted to company wallets at verification.
  IdentityRegistry.sol setCredential(address, bytes32 hash, uint64 expiry),
                      revoke(address), isVerified(address) view.
                      Stores ONLY the credential hash — never PII (GDPR).
  EscrowVault.sol     THE CORE. Holds funds between fund() and release().
                      fund(bytes32 id, address payee, uint256 amount,
                           uint256 fee, bytes32 complianceHash)
                      release(bytes32 id)   — payer or PLATFORM_ROLE
                      refund(bytes32 id)     — payer pre-release, or PLATFORM
                      freeze/unfreeze(bytes32 id) — PLATFORM_ROLE
                      events: PaymentFunded, PaymentReleased, PaymentRefunded,
                              PaymentFrozen
                      Guards: OZ AccessControl (PLATFORM_ROLE) + ReentrancyGuard,
                      checks-effects-interactions, verified-party gate via
                      IdentityRegistry.isVerified.
  AuditAnchor.sol     anchor(bytes32 hash) -> event Anchored(hash, timestamp).

Test every state transition + access-control failure + reentrancy; all green
before wiring the backend.

3. THE SETTLEMENT PORT (already in the backend — implement against THIS)
--------------------------------------------------------------------------------
File: backend/src/modules/settlement/settlement.interface.ts

  export interface FundResult { txHash: string; escrowId: string; }

  export interface Settlement {
    fund(paymentId, payeeWallet, amountMinor, feeMinor, complianceHash): Promise<FundResult>;
    release(escrowId): Promise<{ txHash: string }>;
    refund(escrowId): Promise<{ txHash: string }>;
    anchorDecision(hash): Promise<{ txHash: string }>;
  }

  export const getSettlement: () => Settlement;   // orchestrator calls this
  export const setSettlement: (s: Settlement) => void;  // P1 swaps real impl in

Current default export `simulatedSettlement` returns random-but-valid-looking
tx hashes and escrow ids, no external calls. This is also the ROADMAP risk-R1
fallback: if the real chain integration slips, the demo still runs and the UI is
identical.

P1 deliverable: a `realSettlement: Settlement` (viem-backed) plus a call to
`setSettlement(realSettlement)` at boot. Nothing else in the backend changes.

5. CONTRACT — AMOUNTS, IDS, HASHES (must match the backend exactly)
--------------------------------------------------------------------------------
- Amounts: backend passes minor units (cents/paise) as `amountMinor`/`feeMinor`.
  MockUSDC has 6 decimals. The real settlement layer converts minor units -> USDC
  base units (multiply by 10^(6-2) = 10^4, since minor units are already 1/100).
  Confirm the scaling in one place and unit-test it.
- escrowId: the backend derives the on-chain id as keccak256(paymentUuid). fund()
  returns the id it used; the backend stores it on Payment.escrowId and passes it
  back to release()/refund(). Use bytes32.
- complianceHash: backend computes keccak256 over the decision; passed into fund()
  and also anchored via anchorDecision(). Store on-chain in the Payment struct.
- Wallets: demo wallets are custodial (generated server-side at signup, key in DB,
  DEMO ONLY). The real settlement signs with PLATFORM_PRIVATE_KEY for platform-role
  actions; for payer-funded escrow in the demo, the platform may act on the payer's
  behalf using the stored demo key. Production roadmap: non-custodial payer wallets.

7. SEED DATA THAT TOUCHES THE CHAIN (as of backend step 8)
--------------------------------------------------------------------------------
The demo seed (backend/src/scripts/seed.ts) creates state P1's contracts mirror:
- Every verified user gets a demo wallet address + (DEMO ONLY) private key in the
  DB. When real settlement lands, these are the addresses the faucet mints MockUSDC
  to and that EscrowVault pays out to. Admin has no wallet.
- Every verified user gets a Credential row with a keccak256(userId) hash and an
  anchorTxHash placeholder. The real IdentityRegistry.setCredential(address, hash,
  expiry) should be called with THIS hash so isVerified() gates match the DB.
- ~43 historical COMPLETED payments carry placeholder escrowId/txHashFund/
  txHashRelease. These are history only — the real chain does not need to backfill
  them; only NEW payments created during the demo go through real settlement.
- Seeded actors: novatek@ / chennai@ (companies), priya@ / alex@ (verified
  freelancers), uma@ (KYC pending), sanctioned@ = "SanctionedCo" (OFAC hit),
  admin@. All password demo1234.

When wiring real settlement, mint MockUSDC to the seeded company wallets at boot
(or in a faucet step) and call setCredential for each seeded credential so the
verified-party gate in EscrowVault.fund() passes for the demo actors.
