--------------------------------------------------------------------------------
1. WHAT'S SCAFFOLDED (runnable now, against the REAL backend)
--------------------------------------------------------------------------------
Stack: React 18 + Vite + TypeScript + react-router-dom. Design tokens in plain CSS
(src/styles.css) matching UI_SPEC §1 (dark navy fintech). P3 may layer Tailwind/
shadcn on top later without changing the token names.

Structure (frontend/):
  vite.config.ts    dev proxy: /api -> http://localhost:4000 (REST + ws:true)
  src/lib/api.ts    typed client for every endpoint (imports @gigbridge/shared types)
  src/lib/auth.tsx  AuthProvider: login / me / token in localStorage
  src/lib/ws.ts     useWs() hook -> ws://.../api/v1/ws?token=<jwt>
  src/components/    Layout (role nav), bits (money/Chip/Stat)
  src/pages/
    Login.tsx               demo-account picker, real login
    company/Overview.tsx    stats + payouts table, live via WS
    company/NewPayout.tsx   THE WIZARD: quote -> compliance verdict + agent
                            reasoning -> confirm & settle (all real API)
    freelancer/Home.tsx     balance + received payments, live via WS
    admin/Monitor.tsx       compliance queue (approve/reject) + fraud alerts, live

VERIFIED: `pnpm --filter ./frontend build` passes; running the backend on :4000 and
`vite` on :5173, login through the proxy returns the real seeded user.

--------------------------------------------------------------------------------
2. HOW TO RUN THE WHOLE THING LOCALLY
--------------------------------------------------------------------------------
  1. Postgres up; backend: `cd backend && pnpm prisma migrate dev && pnpm db:seed && pnpm dev`
     (serves :4000). Or `pnpm demo:reset` to restore demo state.
  2. Frontend: `cd frontend && pnpm dev` (serves :5173, proxies /api to :4000).
  3. Open http://localhost:5173 — log in with any demo account (password demo1234):
     novatek@demo.gg (company), priya@demo.gg (freelancer), admin@demo.gg (admin).

--------------------------------------------------------------------------------
3. THE API CONTRACT THE FRONTEND RELIES ON (frozen — BUILD_CONTRACTS §4/§5)
--------------------------------------------------------------------------------
REST base /api/v1. Auth: Bearer <jwt> from /auth/login. Amounts are minor units.
Key calls the scaffold already wires:
  POST /auth/login -> {token, user}
  GET  /fx/quote?pair=EURINR&amount=<minor> -> FxQuote (rate, fee, payeeReceives, vs-PayPal)
  POST /payments {payeeId, srcCurrency, dstCurrency, srcAmountMinor, purposeCode}
       -> {payment, quote, decision:{verdict, agentExplanation}}
  POST /payments/:id/confirm {quoteId} -> Payment (COMPLETED, tx hashes)
  GET  /payments -> Payment[] (role-scoped)
  GET  /admin/queue, POST /admin/queue/:id/resolve {action, note}
  GET  /admin/alerts, /admin/metrics, /admin/rules
  GET  /payments/:id/receipt.pdf, /payments/:id/compliance.pdf (HTML, print-to-PDF)
WebSocket /api/v1/ws?token=<jwt> emits: payment.state, alert.new, notification.new,
metrics.tick. The three dashboards re-fetch on the relevant event -> live timelines.
