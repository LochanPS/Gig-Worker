3. CANONICAL ENUMS AND TYPES (source of truth: /shared/src/types.ts)
--------------------------------------------------------------------------------
  PaymentState = 'DRAFT' | 'COMPLIANCE_CHECK' | 'FLAGGED' | 'REJECTED'
    | 'RATE_LOCKED' | 'FUNDED' | 'SETTLING' | 'COMPLETED' | 'REFUNDED'
    | 'EXPIRED'
  Verdict     = 'APPROVE' | 'FLAG' | 'REJECT'
  Role        = 'COMPANY' | 'FREELANCER' | 'ADMIN'
  KycStatus   = 'PENDING' | 'VERIFIED' | 'REJECTED'
  AlertType   = 'VELOCITY' | 'STRUCTURING' | 'OUTLIER' | 'SANCTIONS'
  Currency    = 'EUR' | 'USD' | 'INR'
  Corridor pairs used in demo: EURINR, USDINR, INRUSD.
  Amounts: integers in minor units (cents/paise) everywhere in API and DB;
  MockUSDC has 6 decimals; conversion happens only in the settlement layer.
  IDs: uuid v4 strings. Payment.escrowId on-chain = keccak256(uuid).

4. REST API CONTRACT (frozen paths; bodies per /shared zod schemas)
--------------------------------------------------------------------------------
  POST /api/v1/auth/register        {email,password,role,country,name...}
  POST /api/v1/auth/login           -> {token, user}
  GET  /api/v1/auth/me
  POST /api/v1/kyc/submit           freelancer docs (mock)
  POST /api/v1/kyb/submit           company details
  POST /api/v1/admin/verify/:userId issues credential + on-chain hash
  GET  /api/v1/credentials/me
  GET  /api/v1/fx/quote?pair=EURINR&amount=50000   (amount in minor units)
       -> {midRate, fee, gasEstimate, payeeReceives, quoteId, expiresAt}
  GET  /api/v1/fx/history?pair=EURINR&days=30
  POST /api/v1/payments             {payeeId, srcCurrency, dstCurrency,
                                     srcAmountMinor, purposeCode,
                                     invoiceRef?} -> payment in
                                     COMPLIANCE_CHECK, then verdict applied
  POST /api/v1/payments/:id/confirm {quoteId} -> locks rate, funds escrow
  POST /api/v1/payments/:id/release
  POST /api/v1/payments/:id/refund
  GET  /api/v1/payments             (role-scoped list)
  GET  /api/v1/payments/:id         (includes timeline[] and compliance)
  POST /api/v1/invoices             {companyId, amountMinor, currency, memo}
  POST /api/v1/invoices/:id/approve -> creates payment draft
  GET  /api/v1/admin/queue          flagged payments
  POST /api/v1/admin/queue/:id/resolve {action:'APPROVE'|'REJECT', note}
  GET  /api/v1/admin/alerts
  GET  /api/v1/admin/metrics
  GET  /api/v1/admin/rules
  GET  /api/v1/payments/:id/receipt.pdf
  Auth: Authorization: Bearer <jwt>. Errors: {error:{code,message}} with
  proper HTTP status. WS auth: ?token=<jwt> query param.

6. SMART CONTRACT INTERFACE (frozen signatures; P1 owns implementation)
--------------------------------------------------------------------------------
  MockUSDC:        standard ERC20 + mint(address,uint256) onlyOwner
  IdentityRegistry: setCredential(address,bytes32 hash,uint64 expiry),
                    revoke(address), isVerified(address) view returns(bool)
  EscrowVault:
    fund(bytes32 id, address payee, uint256 amount, uint256 fee,
         bytes32 complianceHash)            // payer calls after approve()
    release(bytes32 id)                     // payer or PLATFORM_ROLE
    refund(bytes32 id)                      // payer pre-release, or PLATFORM
    freeze(bytes32 id) / unfreeze(bytes32 id)  // PLATFORM_ROLE
    events: PaymentFunded(id,payer,payee,amount,fee,complianceHash),
            PaymentReleased(id), PaymentRefunded(id), PaymentFrozen(id)
  AuditAnchor:     anchor(bytes32 hash) -> event Anchored(hash, timestamp)
  ABI HANDOFF: P1 commits build artifacts to /shared/abis/*.json plus
  /shared/abis/addresses.local.json written by the deploy script on boot.
  Deploy-on-boot: backend runs `forge script` output OR P1 provides a
  TypeScript deploy module `contracts/deploy.ts` (preferred) the backend
  imports and calls when anvil has no code at the expected address.
